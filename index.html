1. 项目概述

1.1 为什么做这个项目

成渝地区将大数据产业列为核心增长极，成都《人才需求清单》一次性集中推出 5610 个优质岗位，本科及以下可投岗位超 4800 个。但对高职专科生而言，面对海量且口径不一的招聘信息，往往陷入"看不懂、投不准"的困境：不清楚哪些岗位真实可达、需要补哪些技能、薪资与技能如何对应。

1.2 业务问题（不是玩数据）

本项目要回答一个具体问题：作为成都的高职大数据专科生，我能投什么岗位、该补什么技能？ 而不是单纯采集与堆砌数据。

1.3 技术链路

项目遵循标准数据分析流程，共五个阶段：

① 数据采集  →  ② 数据清洗  →  ③ EDA 探索分析  →  ④ 可视化  →  ⑤ 结论输出

1.4 可交付成果

  • 一份可溯源的结构化岗位数据集（373 条成都大数据相关岗位）
  • 高职可达性三层模型（L1 可达 / L2 跳一跳 / L3 暂不可达）+ 专升本解锁路径标注
  • 可视化看板（4 张核心图表 + 交互式全景看板）
  • 两张求职决策表：《可投岗位清单》《补技能清单》

2. 数据源与采集方案

2.1 数据源选择原则

官方/公开源优先，不自动化商业招聘平台。官方/公开源零法律风险、结构稳定、可溯源；商业平台用户协议禁止批量抓取、反爬强、存在"幽灵岗位"失真，故本项目仅作合规降级补充。

4.3 补充：技能词频与学习路径（独立数据集）

因主数据集技能列整列缺失，改用 成都五行业数字岗位_1200条.csv（大数据类 n=94，技能覆盖率 82%）分析，结论：

  • 大数据岗核心是数据工程而非算法：高频词为数据治理（19）、数据库（17）、数仓/ETL（合计 14）。
  • 学习路径三层：地基（SQL/Python）→ 通用语言（数据治理、数仓建模、ETL）→ 加分项（Java、大模型、数据中台）。
  • 方法论诚实披露：标题级技能抽取导致"溢价"混杂职级信号（如"数据中台"岗天然资深），故该溢价仅表征"关联岗位档次"，不可读成"学会即涨薪"。

5. 业务结论与项目价值

5.1 四结论（落地，可直接指导求职决策）

  1. 谈薪看中位数：以 18k 为基准锚点，不被"平均薪资"误导。
  2. 学历非天花板：学历有溢价，但"学历不限"高薪岗证明能力可对冲学历约束。
  3. 真实可投面 63.8%：聚焦 L1/L2 共 238 个岗位；其中 216 个靠专升本解锁（ROI 最高单点杠杆）。
  4. 主攻数据开发/ETL：132 个岗居首（35%）、专科可达性最高，技术栈对齐 SQL+数仓+ETL，不必先卷算法。

5.2 项目价值

  • 对个人：把"模糊的求职焦虑"转化为"分层可达、方向明确"的决策依据，作品集本身即用于对冲"经验不足"。
  • 对面试官：展示的是一条完整严谨的数据分析链路（采集合规→清洗留痕→EDA→可视化→结论），以及主动披露数据局限的判断力——这正是数据分析岗核心素质。

6. 项目总结、局限性与后续优化

6.1 项目总结

本项目以"专科生如何在成都投大数据岗"为业务牵引，完成 373 条岗位数据的采集→清洗→EDA→可视化→结论全流程，构建高职可达性三层模型，并量化出可投面 63.8%、主攻方向数据开发/ETL、专升本为最高 ROI 杠杆等关键结论，可直接支撑简历投递决策。

6.2 局限性（如实披露，反成加分项）

  1. 来源偏差：以单一招聘平台公开信息为主，未覆盖官方公共招聘网与全部商业平台，结论不可外推为整体市场。
  2. 时效滞后：快照为 2026-09-09 单点，非趋势数据。
  3. 口径损失：薪资混合区间/年薪/面议，标准化为月薪中位存在精度损失（已保留原文溯源）。
  4. 主观判定：L1/L2/L3 分层基于个人画像（专科+专升本计划）主观标注。
  5. 样本规模：373 条中大专样本仅 17 个（4.6%），细分维度置信区间较宽。
  6. 技能缺失：主数据集技能列整列缺失，技能结论来自替代数据集（已注明数据边界）。

6.3 后续可优化方向

  1. 扩源扩量：并入官方公共招聘网、市属国企公告，向 ≥800 条目标扩展，提升细分统计可信度。
  2. 趋势化：建立周级快照，跟踪薪资/可达性随时间变化。
  3. 技能补全：攻克详情页验证码后回填技能字段，做真实 JD 级技能词频与薪资回归。
  4. 可交互化：将看板接入轻量 Web（如 Streamlit/静态页），支持按岗位族/区县筛选，并补充 API 服务输出《可投岗位清单》《补技能清单》。

一、项目背景与业务目标

背景

成渝地区双城经济圈将大数据相关产业列为核心增长极——四川把人工智能列为"一号创新工程"并建设行业高质量数据集与语料库，重庆将软件和信息服务业列为新增万亿级集群。《成都市人才需求清单》一次性集中推出 5610 个优质岗位，其中硕士及以上仅约 800 个，本科及以下可投岗位超 4800 个。但对高职专科生而言，面对海量且口径不一的招聘信息，往往陷入"看不懂、投不准"的困境：不清楚哪些岗位真实可达、需要补哪些技能、薪资与技能如何对应。

业务目标

本项目旨在回答一个具体的求职业务问题——"作为成都的高职大数据专科生，我能投什么岗位、该补什么技能"，而非单纯采集与堆砌数据。通过采集成都官方公开发布的紧缺人才目录、产业规划与岗位信息，构建一份可溯源、可增量维护的结构化数据集，量化高职（含专升本路径）可达岗位与技能缺口，输出可直接指导投递决策的清单与看板。

可交付目标：

  1. 构建一份可溯源、可增量维护的成都数据类岗位结构化数据集（MVP 阶段 200–300 条官方高质量记录，中长期扩展至 ≥800 条有效记录）；
  2. 量化高职可达岗位的占比、薪资与技能结构；
  3. 输出《可投岗位清单》《补技能清单》两张求职决策表；
  4. 沉淀一个可运行的分析项目（EDA + 可视化 + 后端 API），直接写入简历。

二、项目整体流程架构

项目遵循标准数据分析技术链路，共五个阶段：

① 数据采集  →  ② 数据清洗  →  ③ EDA 探索分析  →  ④ 可视化  →  ⑤ 结论输出
  • ① 数据采集：按"政策规划（L0）→ 紧缺目录（L1）→ 官方渠道真实岗位（L2）"三层结构采集，逐条保留 source_url 与 snapshot_date（采集快照日期），保证可溯源、可趋势化。
  • ② 数据清洗：字段归一（岗位名 / 技能标签映射表）、薪资口径标准化为"月薪中位数 / 元"（保留 salary_raw 原文）、去重（源 + 哈希主键）、高职可达性打标（L1 / L2 / L3 ＋ unlock_by 解锁路径）。
  • ③ EDA 探索分析：学历 / 经验要求分布、薪资分布、技能词频与薪资关联、政策赛道 ↔ 岗位映射、岗位地域分布等。
  • ④ 可视化：岗位缺口地图（城市 × 岗位族 × 紧缺度）、技能-薪资关联图、高职可达岗位看板。
  • ⑤ 结论输出：《可投岗位清单》《补技能清单》两张决策表 ＋ 作品集可运行项目（含后端 API 服务）。

每一层均强制带 snapshot_date 与 source_url，保证全链路可溯源、可趋势化。

四、项目预期分析问题（5 个业务问题）

  1. 可达性：成都数据类岗位对学历与经验的要求分布如何？高职专科生（含专升本路径）实际可达岗位占比多少？
  2. 岗位族差异：数据开发 / 数据分析 / 数据标注 / BI / 数据运维 / ETL 各岗位族的薪资区间与核心技能要求有何差异？
  3. 技能优先级：哪些技能出现频次最高、且与薪资正相关？应优先补齐哪几项（按"频次 × 薪资增益 × 学习成本"排序）？
  4. 政策-需求匹配：政策规划的产业赛道（人工智能 / 软件信息服务 / 工业数据）与实际岗位需求是否匹配？哪些方向对高职生更友好？
  5. 地域分布：岗位在成都各区县的分布与紧缺度如何？是否值得向都市圈（德眉资）拓展求职？

五、项目局限性说明（如实披露，面试加分项）

  1. 来源偏差：以官方 / 公开目录为主，未覆盖商业招聘平台全量，样本偏向"规划导向"岗位，结论不可外推为整体市场供需。
  2. 时效滞后：官方目录多为年度报告 / 季度发布，数据非实时；已用 snapshot_date 快照机制缓解趋势缺失，但仍存在时滞。
  3. 口径损失：薪资多为区间或"面议 / 年薪 / 带提成"混合口径，标准化为月薪中位数存在精度损失，已保留 salary_raw 原文溯源。
  4. 主观判定：L1 / L2 / L3 可达性分层基于个人画像（专科 ＋ 专升本计划）做主观标注，unlock_by 解锁路径为建议性而非雇佣方承诺。
  5. 样本规模：官方源有效岗位有限（MVP 200–300 条），统计置信区间较宽，细分维度（如单区县 × 单一岗位族）样本可能不足。
  6. 合规边界：数据仅用于个人学习研究与求职，不对外分发原始明细，成果仅发布聚合统计结论；未获取任何求职者个人信息。

三、Python requests + bs4 核心代码框架（教学骨架）

以下骨架面向官方静态页面（最稳妥、零风险）。URL 与选择器需你用浏览器 F12 自行核对后填入，不要直接整套照搬运行。重点看思路：合规请求 → 限速 → 解析 → 抽取字段。
"""
成都官方紧缺岗位采集 · 核心代码框架（教学骨架）
目标：从服务端渲染的官方静态页面提取岗位信息
注意：本脚本为思路骨架，URL 与选择器需自行核对；禁止对商业平台高频批量抓取。
"""
import time
import requests
from bs4 import BeautifulSoup
import pandas as pd

# ---------- 1. 基础配置（学生需自行调整） ----------
HEADERS = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...",  # 填真实 UA
    "Accept-Language": "zh-CN,zh;q=0.9",
}
REQUEST_INTERVAL = 2.0   # 请求间隔（秒），保守取 2~3s
REQUEST_TIMEOUT  = 10    # 超时（秒）
BASE_URL = "https://www.chengdu.gov.cn/.../xxx.shtml"  # TODO: 替换为真实官方页面

# ---------- 2. 合规请求（带 UA、超时、异常捕获） ----------
def fetch_page(url):
    try:
        resp = requests.get(url, headers=HEADERS, timeout=REQUEST_TIMEOUT)
        resp.encoding = resp.apparent_encoding   # 防中文乱码
        if resp.status_code == 200:
            return resp.text
        print(f"[WARN] 状态码 {resp.status_code} @ {url}")
        return None
    except Exception as e:
        print(f"[ERROR] 请求失败 {url}: {e}")
        return None

# ---------- 3. 解析（BeautifulSoup 定位卡片 → 逐字段抽取） ----------
def parse_jobs(html):
    soup = BeautifulSoup(html, "html.parser")
    records = []
    # TODO: 用 F12 核对真实容器/字段选择器，下面为示意
    cards = soup.select("div.job-card-pc-container")   # 示意选择器
    for card in cards:
        job = {
            "job_title_raw": card.select_one("div[title]").get("title", ""),
            "company_name":  card.select_one(".company-name").get_text(strip=True),
            "salary_raw":    card.select_one(".job-salary").get_text(strip=True),
            "district":      card.select_one(".job-dq-box .ellipsis-1").get_text(strip=True),
            # 其余字段同理，按需抽取；标签需分类（学历/经验/福利）
        }
        records.append(job)
    return records

# ---------- 4. 主流程（单线程串行 + 限速） ----------
def main():
    html = fetch_page(BASE_URL)
    if not html:
        return
    records = parse_jobs(html)
    print(f"本页抽取 {len(records)} 条")
    df = pd.DataFrame(records)
    df.to_csv("jobs_raw.csv", index=False, encoding="utf-8-sig")  # 落盘见第五节
    time.sleep(REQUEST_INTERVAL)   # 限速，绝不套多线程

if __name__ == "__main__":
    main()

四、采集时需注意的爬虫规范（合规与风控）

  1. 先读 robots.txt：请求前访问目标站 /robots.txt，遵守 Disallow 与 Crawl-delay；官方/开放平台以平台标注的开放属性为准。
  2. 控制频率：单线程、间隔 2–3s、单轮 ≤ 25 次；避开访问高峰；失败即退避，不暴力重试。
  3. 合理请求头：设置真实 UA、超时、重试退避；不伪造、不伪装成搜索引擎。
  4. 不越界：不登录抓取、不绕过验证码、不破解接口签名；只采企业公开发布的岗位信息。
  5. 不碰个人信息：绝不采集姓名/电话/简历等，《个人信息保护法》是法律红线，与"能不能爬"无关。
  6. 注明来源：开放平台协议通常要求成果注明"数据来源 + 下载日期"——这本身就是简历里的合规加分项。
  7. 不二次分发：原始数据不打包外传；对外只发布聚合统计结论。
  8. 商业平台红线：BOSS/智联/前程用户协议禁止批量抓取 → 不做自动化；猎聘仅作降级补充并守阈值。

2.2 缺失值处理

import re, numpy as np
for c in ["月薪下限_元","月薪上限_元","月薪中位_元"]:
    df[c] = pd.to_numeric(df[c], errors="coerce")   # 空串→NaN，便于统计缺失

# 缺失薪资：用"薪资原文"回补（只动空值，已有数值不动）
def parse_salary(raw):
    if not raw: return (np.nan, np.nan)
    m = re.search(r"(\d+(?:\.\d+)?)\s*-\s*(\d+(?:\.\d+)?)\s*k", raw)  # 区间 12-18k
    if m: return float(m.group(1))*1000, float(m.group(2))*1000
    m = re.search(r"(\d+(?:\.\d+)?)\s*k", raw)                        # 单值 40k
    if m: v = float(m.group(1))*1000; return v, v
    return (np.nan, np.nan)

mask_null = df["月薪下限_元"].isna() | df["月薪上限_元"].isna()
for i in df[mask_null].index:
    lo, hi = parse_salary(df.at[i,"薪资原文"])
    df.at[i,"月薪下限_元"] = lo
    df.at[i,"月薪上限_元"] = hi
    df.at[i,"月薪中位_元"] = (lo+hi)/2 if pd.notna(lo) and pd.notna(hi) else np.nan
    df.at[i,"薪资口径标记"] = "存疑(原文回补)"   # 关键：保留可追溯，不偷偷当真值

# 技能字段：占位符清洗，避免污染词频（本集全部缺失，直接标记）
SKILL_PH = "（源站详情页触发IP验证码，未获取）"
df["技能可用"] = ~df["技能要求"].str.contains("未获取", na=False)
df.loc[df["技能要求"] == SKILL_PH, "技能要求"] = np.nan

为什么：缺失值不盲目删、不瞎填。薪资用原文回补但打"存疑"标记，既保住样本量又不影响可信统计——这是严谨性的体现。

2.3 异常值处理（只标记、不删行）

df["薪资异常"] = ""
m_mid = (df["月薪中位_元"] < df["月薪下限_元"]*0.9) | (df["月薪中位_元"] > df["月薪上限_元"]*1.1)

m_rev = df["月薪下限_元"] > df["月薪上限_元"]
df.loc[m_rev, "薪资异常"] += "上下限颠倒;"
hi_thr, lo_thr = df["月薪中位_元"].quantile(0.995), df["月薪中位_元"].quantile(0.005)
m_ext = (df["月薪中位_元"] > hi_thr) | (df["月薪中位_元"] < lo_thr)
df.loc[m_ext & (df["薪资异常"]==""), "薪资异常"] = "极端值(保留)"

为什么：异常值处理原则是"先诊断、后决策"。本集有 4 条极端高薪（架构/技术经理），直接删除会损失业务信息，故标记后在统计时按需剔除。

2.4 字段类型转换（含经验要求归一化）

def parse_exp(s):
    s = (s or "").strip()
    if "不限" in s or s == "无": return (0.0, np.nan)
    m = re.search(r"(\d+)\s*-\s*(\d+)\s*年", s);  if m: return float(m.group(1)), float(m.group(2))
    m = re.search(r"(\d+)\s*年\s*以上", s);       if m: return float(m.group(1)), np.nan
    m = re.search(r"(\d+)\s*年\s*以下", s);       if m: return 0.0, float(m.group(1))
    m = re.search(r"(\d+)\s*年", s);              if m: return float(m.group(1)), float(m.group(1))
    return (np.nan, np.nan)

df[["经验下限_年","经验上限_年"]] = df["经验要求"].apply(lambda x: pd.Series(parse_exp(x)))
df["经验缺失"] = df["经验下限_年"].isna()

edu_order = ["大专","学历不限","本科","硕士","博士"]
df["学历要求"] = pd.Categorical(df["学历要求"], categories=edu_order, ordered=True)
df["可达性"]   = pd.Categorical(df["可达性"],   categories=["L1","L2","L3"], ordered=True)
df["快照日期"] = pd.to_datetime(df["快照日期"], errors="coerce")

df.to_csv("data/clean/成都大数据岗位_清洗后.csv", index=False, encoding="utf-8-sig")

三、4 条面向应届生求职的落地业务结论

要求：结论不能空泛，必须能直接指导"投不投、补什么、怎么谈薪"。

结论 1：谈薪看中位数，别被"平均薪资"带偏

  • 数据：薪资中位数 18,000 元，均值 22,097 元，差 4,097 元；75% 岗位落在 12,500~25,000 元。
  • 落地建议：面试谈薪、填期望薪资时以 18k 为基准锚点。均值被少数 30k+ 架构/资深岗拉高，若以均值自我预期，容易高估、错失匹配岗位。
  • 面试讲法："我汇报薪资一律报中位数，因为分布右偏，均值没有代表性。"

结论 2：学历有溢价，但"学历不限"高薪岗证明专科不是天花板

  • 数据：大专中位 13,500 → 本科 17,500（溢价 +29.6%）→ 硕士 22,500；但"学历不限"岗位中位 25,000 > 本科。
  • 落地建议：专升本值得做（回报率量化在第 3 点），但不必因"大专"彻底躺平——把项目、技能做扎实，可以直接冲"学历不限"的高薪岗。
  • 面试讲法："学历是门槛之一不是天花板；我用作品集项目证明工程能力，对冲学历约束。"

结论 3：专科生真实可投面 = 63.8%，把目标定在合理区间

  • 数据：可达性 L1（现在能投）12 个 + L2（跳一跳可达）226 个 = 238 个，占 63.8%；L3 暂不可达 135 个。
  • 落地建议：投简历聚焦 L1/L2 共 238 个岗位，不要因"要求本科"就放弃全部；其中 216 个岗位靠"专升本"解锁（占 57.9%），说明升本是 ROI 最高的单点杠杆。
  • 面试讲法："我把岗位按可达性分层，真实可投面 63.8%，升本能再解锁 216 个，所以我的规划是边升本边投 L2。"

结论 4：主攻"数据开发/ETL"，技术栈对齐数仓 + ETL + SQL

  • 数据：岗位族招聘量第一是 数据开发/ETL（132 个，占 35%），且其中 L2 有 89 个（专科可达性最高）。
  • 落地建议：简历项目、刷题、实习方向全部对齐"数据开发/ETL"——SQL、数仓建模、ETL 调度；不必先去卷算法（算法岗量小、门槛高）。
  • 面试讲法："我用数据定位出主攻方向是数据开发/ETL，所以我重点练的是 SQL 和数仓 ETL，而不是算法。"

四、⚠️ 一个必须讲清的方法论陷阱（面试加分）

上表里「数据中台 +30,500」看起来很诱人，「数据库 −4,500」看起来像坑。

但这个溢价不能直接读成"学 A 比学 B 多赚三万"。

原因：溢价是拿「标题含该技能的岗位」的薪资中位，去比整体中位。而岗位标题本身就自带职级信号：

  • 标题含「数据中台」的岗位，通常是平台架构/中台建设类，本身就是资深岗 → 薪资天然高
  • 标题含「数据库」的岗位，很多是数据库运维/DBA 初级岗 → 薪资天然低
  • 标题含「数据标注」的岗位，是劳动密集型岗 → 薪资最低

所以这个指标衡量的是"这个关键词关联着什么档次的岗位"，而不是"学会这个技能能涨多少薪"。

要真正测技能回报，需要控制职级、经验、学历做回归——那就超出这份数据的字段范围了。

能在面试里主动说出这一层，比背出"数据中台薪资 45k"要有价值得多。

Q1：你这个项目的数据从哪来？合法吗？

答：来自招聘网站公开发布的岗位信息，采集时我先读 robots.txt、单线程限速 2–3 秒、单轮不超过 25 次；绝不采集任何求职者个人信息，不绕过验证码，原始数据不外传，只发布聚合统计。每一步都留了来源 URL 和快照日期。

答：是我基于"专科 + 专升本计划"这个个人画像做的主观标注，L1 学历经验完全匹配、L2 补一项能力或 1–2 年经验可达、L3 需先解决学历硬门槛。我在报告里明确写了这是主观判定、unlock_by 是建议而非承诺——它用于给自己做决策参考，不是给企业的客观标准。

Q4：技能字段缺失你怎么办的？

答：主数据集 373 条技能整列缺失（详情页触发验证码）。我的处理是不编造、不填补，而是换用另一份带技能标签的 1200 条数据集，并且先做覆盖率审计——发现大数据类覆盖率 82%、数据分析类只有 14%，所以只对可信子集下结论。这种"先审计再推断"的判断本身就是加分点。

Q5：数据中台薪资 45k，是不是最值得学？

答：不一定。那个"溢价"是拿"标题含该词的岗位"去比整体中位，但标题自带职级信号——含"数据中台"的多是资深架构岗，薪资天然高。所以这个指标衡量的是"关联什么档次岗位"，不是"学会能涨多少薪"。要真测回报得控制职级/经验做回归，超出当前数据范围。我能讲清这个陷阱，比背一个数值更有价值。

Q6：专科生在大数据岗是不是没机会？

答：客观说，大数据岗本身对专科不友好——大数据类样本里大专只占 4.3%，76.6% 要求 3 年以上经验。但我的项目量化出整体可投面仍有 63.8%（含数据开发/ETL、数据分析运营、数据运维等 L2 岗），且专升本能再解锁一大批。我的策略是：升本 + 从 L2 切入 + 用作品集项目对冲"经验不足"。这不是画饼，是把门槛说清楚后的可执行路径。

Q7：你用到哪些工具/技术？

答：Python 做清洗和 EDA（pandas 风格的 csv/re 处理），matplotlib 画图，输出自包含 HTML 看板（纯 SVG，可离线打开）。我个人更看重工程严谨性：清洗留痕、异常只标不删、结论可溯源。

Q8：如果让你再做一遍，你会改进什么？

答：四点——① 扩源扩量到 ≥800 条、并入官方公共招聘网提升代表性；② 做周级快照看趋势；③ 攻克验证码回填真实技能字段做 JD 级词频；④ 把看板接成可交互 Web，支持按岗位族/区县筛选并输出《可投岗位清单》。
